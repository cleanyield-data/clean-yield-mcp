# Pruebas del 11/11/2026: listar sin clave (Glama)

Problema: Glama construye el Dockerfile **sin APIFY_TOKEN** y pide `tools/list` por stdio. La versión 1.0.0 hacía `process.exit(1)` sin clave, por eso Glama marcaba "This server cannot be deployed" y calidad C.

## 1. ¿El servidor oficial de Apify lista sin clave?

No. Probado con `@apify/actors-mcp-server` **0.20.2** (la fijada) y **0.21.6** (la última), sin `APIFY_TOKEN` y con `initialize` + `notifications/initialized` + `tools/list` por stdio:

```
ERROR APIFY_TOKEN is required but not set in the environment variables or in ~/.apify/auth.json
```

Las dos cortan antes de responder. Por eso se tomó el **camino 2**: servidor stdio propio, sin dependencias (`index.js`).

## 2. Qué hace el servidor nuevo (1.0.1)

- `initialize`, `notifications/initialized`, `ping`, `tools/list` responden **sin clave y sin red**. `tools/list` devuelve siempre las 5 herramientas de `tools.json`.
- `tools.json` se genera con `npm run build:tools` desde la API pública de Apify (`GET /v2/acts/cleanyield~<actor>` → `pricingInfos`; `GET .../builds/default` → input schema publicado). Se toma el precio **vigente hoy**; un precio programado (ATS Jobs el 24/11) se muestra como "From 2026-11-24 ...", nunca como el actual.
- `tools/call` sin clave → resultado `isError: true` con cómo sacar el token (Apify Console > Settings > API & Integrations; plan gratis con USD 5/mes).
- `tools/call` con clave → se delega en el servidor oficial (`@apify/actors-mcp-server@0.20.2`, `--tools` con los 5 Actors). El nombre propio se mapea al suyo por el Actor (`cleanyield--<actor>`, o su `title` `cleanyield/<actor>`). Su resultado se devuelve **sin cambios**; como el oficial solo devuelve el resumen de la corrida y remite a su herramienta `get-dataset-items` (que nosotros no exponemos), el servidor pide las filas a ese mismo servidor oficial y las **agrega** al final del resultado (hasta `CLEAN_YIELD_MAX_ITEMS`, 100 por defecto). Lo mismo pasa con 0.21.6 (tampoco trae las filas).
- Delegar resultó estable (3 corridas reales sin fallas: node local con binario instalado, node local con `npx` y Docker), así que no hizo falta la alternativa de llamar la API directo.

## 3. Prueba como Glama (Docker, sin clave, sin red)

```
docker build -t cymcp .
printf "<initialize>\n<initialized>\n<tools/list>\n" | docker run -i --rm --network none cymcp
```

Nota del entorno: acá la construcción pasa por un proxy que intercepta TLS y Docker Hub devolvió 429. Para construir se bajó la misma imagen `node:22-slim` de `mirror.gcr.io` y se usó una copia del Dockerfile con 2 líneas extra solo para este entorno (`COPY ca-bundle.crt` + `NODE_EXTRA_CA_CERTS`). El Dockerfile del repo no las tiene. La corrida fue con `--network none`: listar no necesita red.

## 5. Errores encontrados y arreglados durante la prueba

1. Al cerrarse stdin el servidor hacía `process.exit(0)` y en Docker (stdout por pipe) cortaba la respuesta de `tools/list` (66 KB de ~80 KB). Ahora espera a que termine de escribir.
2. Al limpiar HTML de las descripciones se borraban marcadores como `<company>` en URLs de ejemplo. Ahora solo se sacan etiquetas HTML reales.
